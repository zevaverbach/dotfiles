**On the underlying lesson**

The stylua thing is worth pocketing: *config discovery via parent-walk is invisible until it breaks, and it breaks specifically at symlink boundaries*. The same pattern bites people with `.eslintrc`, `pyproject.toml`, `.editorconfig`, `tsconfig.json`, etc. When config "isn't being picked up," the first question to ask is **where does the tool actually start walking from?** — almost always the resolved real path of the file being processed, not the path the user typed. Then **what's the closest ancestor that holds the config?** If those two directories aren't on the same trunk of the filesystem tree, the tool finds nothing.

The fix is always one of three: (a) put the config closer to the file's real location, (b) symlink the config too, or (c) tell the tool explicitly where to look via a CLI flag.
