## First — exercise 10 isn't passing yet

```go
func (r *Repeater) Read(p []byte) (int, error) {
	numAppended := 0
	for range r.Remaining {
		p = append(p, r.Char)   // ← same bug as Push, one layer deeper
		numAppended++
	}
	...
	return r.Remaining, nil
}
```

It's the **same slice-header mistake as `Push`**, which is exactly why it's worth sitting with. Three questions, no answers:

1. **`append` on `p` writes past the end of what the caller can see.** A caller does `buf := make([]byte, 2); r.Read(buf)` and then looks at `buf[:n]`. Your first `append` puts the byte at index `len(p)` — index 2 — which is *outside* `buf`. And, as with `Push`, `p = append(...)` only rebinds your local header. So: which indices of `p` does the caller actually read, and how do you put bytes there?
2. **`len(p)` never appears in your function.** The contract calls it the caller's budget. What should happen when `Remaining` is 1000 and `len(p)` is 2 — and what does your loop currently do in that case?
3. **The return value is bytes remaining, not bytes written.** You already computed the right number in `numAppended`. And consider `Repeater{Char: 'x', Remaining: 5}` read with a 5-byte buffer: after that read `Remaining` hits 0, so your `EOF` branch fires — did the caller ever learn about those 5 bytes?

Take the same "write into the buffer I was handed" idea and it collapses into a few lines.
